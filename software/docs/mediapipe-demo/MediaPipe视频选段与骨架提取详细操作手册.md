# MediaPipe视频选段与骨架提取详细操作手册

适用电脑：当前这台 Windows 电脑。项目目录：`E:\Desktop\项目`。更新日期：2026年11月22日。

从GitHub取得公开副本的读者：仓库的 `software` 才是本手册所说的项目目录。将下面的 `E:\Desktop\项目` 换成自己实际的 `software` 绝对路径，再按软件README准备本机 `.venv-sign` 环境；不要复制作者的虚拟环境。手册中的当前六词是作者本机维护范围，不表示公开包自带这些识别权重。

这份手册按第一次操作来写，从打开相机开始，做到“原视频与骨架同步对照”，并说明怎样接回项目的统一训练页面。演示以“需要”为例，词名用于说明拍摄内容；骨架提取程序不读这个词名来猜识别答案。

**做到第10章，你会得到真实视频的选段记录、骨架叠加视频、左右同步对照视频和178维特征文件。它们不等于训练完成。** 第11章是继续训练时的页面操作，不是本次已经执行的训练。

配套工具已经放在项目中：`E:\Desktop\项目\scripts\mediapipe-demo.py`。本手册中的 `check / select / mark / extract / play` 都是实际实现的命令。无需自己新建Python文件，也无需把整段程序手工粘贴进终端。

## 1 先弄清楚这次演示的六个动作

| 顺序 | 你要做什么 | 做完得到什么 |
|---|---|---|
| 1 | 用Windows相机录一条完整动作 | MP4原视频 |
| 2 | 将原视频复制到指定文件夹 | 路径固定的演示素材 |
| 3 | 打开选段窗口，标记开始和结束 | JSON选段记录，原片不变 |
| 4 | 在PowerShell运行提取命令 | MediaPipe逐帧分析、导出结果 |
| 5 | 打开同步对照视频 | 左边原画面，右边同一帧的骨架 |
| 6 | 查看摘要和特征形状 | 帧数、时间范围、跟踪情况和178维数据 |

“选段”选的是原视频中的时间范围，不是抠图。MediaPipe负责定位关键点。程序把关键点连起来才形成骨架图；TCN训练是使用这些特征学习动作类别的后续过程。

## 2 准备电脑和拍摄环境

### 2.1 确认项目仍在原位置

1. 打开文件资源管理器，即任务栏上的黄色文件夹。
2. 单击窗口上方的地址栏。
3. 输入 `E:\Desktop\项目`，按回车。
4. 确认能看到 `scripts`、`server`、`web` 等文件夹。
5. 后面的命令全部按这个路径编写。如果换了电脑或移动了项目，路径和Python环境必须重新核对。

### 2.2 摆好摄像头和人

1. 把摄像头固定好，不拿着摄像头边晃边拍。
2. 面向摄像头，保证头部、双肩、上半身和整个动作范围内的双手都能入镜。
3. 先做一次完整动作检查范围，尤其查看指尖会不会超出画面。
4. 光线从正面或侧前方照过来，避免背后窗户太亮导致人和手变黑。
5. 不要让手一直挡在另一只手后面，也不要紧贴镜头。
6. 正常速度做动作，不为了得到骨架而刻意做成不自然的慢动作。
7. 建议此次录制约6—10秒，包含准备、一次完整动作和结束。这里是演示长度建议，不是动作必须持续这么久。
8. 工具要求原视频不超过30秒；建议使用720p或1080p、30fps。选段最多1024帧。

### 2.3 本次需要哪些软件

- Windows自带“相机”：拍摄原视频。
- Windows PowerShell：输入后文的命令。
- 项目自带 `.venv-sign` Python环境：运行OpenCV、MediaPipe和NumPy。
- 工具自己的回放窗口：选段和播放AVI，不要求安装额外视频播放器。

这条骨架演示流程不需要先启动网页后台、不需要登录项目账号，也不需要下载新的MediaPipe权重。当前本机依赖已通过空白画面检查；换电脑不代表自动具备同样环境。

## 3 打开相机并拍摄原视频

### 3.1 打开Windows相机

1. 单击Windows“开始”按钮。
2. 输入“相机”。
3. 单击搜索到的“相机”应用。
4. 如果系统询问摄像头使用权限，由你根据提示允许本次拍摄。
5. 如果看到的是拍照按钮，找到摄像机形状的“视频”模式按钮，切换到录像。
6. 如果电脑有多个摄像头，使用切换摄像头按钮，直到预览中出现你要拍摄的画面。
7. 如设置中有视频质量选项，可选720p或1080p、30fps。不同Windows版本的按钮位置可能不同，以“视频”“视频质量”等名称识别。

### 3.2 先预演一次

1. 先不按录像，观察预览。
2. 双手按既定“需要”动作做一次，确认全程不出画。
3. 调整座位或摄像头距离，让双肩和指尖都清楚。
4. 如果画面黑或提示摄像头被占用，先关闭其他正在使用摄像头的会议软件或浏览器页面，再回到相机。

### 3.3 正式拍一条

1. 单击“开始录制”按钮，确认计时开始。
2. 保持准备姿势约1秒，让录制稳定下来。
3. 做一次完整“需要”动作，不把多个不同词连在这一条演示样本里。
4. 完成后保留短暂停顿；若后续要检查双手出画结束，再自然收手并让画面保留约1秒真实结束尾段。
5. 单击停止按钮，等相机保存完毕。
6. 单击最近一次录制的缩略图，播放刚才的视频。
7. 确认开始、主体和结束都拍到了，没有只录到最后半个动作。

手语动作本身按项目采用的示范和已确认定义完成。本手册教的是录制和提取操作，不重新定义“需要”的手语含义。

### 3.4 找到保存的MP4文件

1. 在相机的回看页面寻找“打开文件夹”或“在文件夹中显示”。
2. 如果没有该入口，打开文件资源管理器，查看“图片”中的“相机胶卷”。Windows通常保存到这里；图片目录被重定向时，也可能在OneDrive图片目录。
3. 按“修改日期”排序，找到刚拍的那条视频。
4. 双击播放确认内容，不要仅凭文件名猜。
5. 在资源管理器开启“文件扩展名”。Windows 11通常是“查看→显示→文件扩展名”；Windows 10通常在“查看”选项卡勾选。
6. 确认文件实际后缀是 `.mp4`。不要将其他格式仅通过重命名假装成MP4。
7. 关闭回放，返回文件所在文件夹，保留这个窗口，后面要复制它。

## 4 打开PowerShell并准备文件夹

### 4.1 打开终端

1. 单击Windows“开始”按钮。
2. 输入 `Windows PowerShell`。
3. 单击“Windows PowerShell”打开。普通权限即可，不需要“以管理员身份运行”。
4. 窗口中会出现类似 `PS C:\Users\22984>` 的提示符。
5. 以下代码框中只复制命令本身，不复制代码框边框，也不手动输入 `PS ...>`。
6. 每次粘贴一条完整命令，按一次回车，等它执行完再输入下一条。

### 4.2 进入项目目录

复制这一整行，粘贴进PowerShell，按回车：

```powershell
Set-Location -LiteralPath "E:\Desktop\项目"
```

核对当前目录：

```powershell
Get-Location
```

预期输出包含 `E:\Desktop\项目`。如果提示路径不存在，先回到资源管理器核对路径，不要继续执行后面的相对路径命令。

### 4.3 建立演示素材目录

```powershell
New-Item -ItemType Directory -Force -Path ".\data\mediapipe-demo\input", ".\data\mediapipe-demo\selections", ".\data\mediapipe-demo\output"
```

这是创建文件夹，文件夹已经存在也可以运行。它不会清空已有文件。

创建后目录用途如下：

```text
E:\Desktop\项目\data\mediapipe-demo\
├─ input\          放原视频副本
├─ selections\     放选段记录
└─ output\         放骨架视频和特征
```

### 4.4 将刚才拍的视频放进去

1. 回到第3章找到的相机视频所在文件夹。
2. 单击刚才的视频，按 `Ctrl+C` 复制。
3. 打开另一个资源管理器窗口，地址栏输入 `E:\Desktop\项目\data\mediapipe-demo\input`，按回车。
4. 按 `Ctrl+V`，等待复制完成。
5. 单击复制进来的文件，按 `F2` 重命名。
6. 将完整名称改为 `need-01.mp4`，按回车。检查不是 `need-01.mp4.mp4`。
7. 如果已经有同名文件，保留旧文件，把新文件命名为 `need-02.mp4`；同时把后续命令中的 `need-01` 改成 `need-02`。

回到PowerShell，检查文件：

```powershell
Get-Item -LiteralPath ".\data\mediapipe-demo\input\need-01.mp4"
```

预期能看到文件名、修改时间和非零大小。文件不存在时，先核对复制位置和扩展名。

## 5 检查工具和MediaPipe环境

### 5.1 确认解释器与脚本存在

依次运行：

```powershell
Test-Path -LiteralPath ".\.venv-sign\Scripts\python.exe"
```

```powershell
Test-Path -LiteralPath ".\scripts\mediapipe-demo.py"
```

两条命令都应输出 `True`。若是 `False`，检查是否进入了正确项目目录，不要直接换成系统 `python` 碰运气。

### 5.2 运行环境检查

```powershell
& ".\.venv-sign\Scripts\python.exe" -B ".\scripts\mediapipe-demo.py" check
```

正常会看到“环境检查通过”和“178维特征”。这一步只处理一张程序生成的空白图，不打开摄像头、不读取你的视频。

参数逐项解释：

| 命令部分 | 含义 |
|---|---|
| `&` | PowerShell用它执行后面带引号的程序路径，不能漏掉 |
| `.\.venv-sign\Scripts\python.exe` | 本项目已经安装MediaPipe的Python |
| `-B` | 不生成Python字节码缓存，不影响结果 |
| `.\scripts\mediapipe-demo.py` | 本次配套的演示工具 |
| `check` | 检查依赖和跟踪图是否可运行 |

可能先出现MediaPipe英文 `INFO` 或 `WARNING`。看最后是否出现“环境检查通过”；只有警告而没有失败不代表不能运行。若出现 `Traceback`、`操作失败` 或没有通过提示，先按第13章处理。

## 6 打开原视频并精确标记时间

### 6.1 启动选段窗口

回到PowerShell，粘贴下面一整行后按回车：

```powershell
& ".\.venv-sign\Scripts\python.exe" -B ".\scripts\mediapipe-demo.py" select --video ".\data\mediapipe-demo\input\need-01.mp4" --selection ".\data\mediapipe-demo\selections\need-01.json"
```

这时程序先检查视频时长和时间戳，再打开 `MediaPipe Demo - Select` 窗口。扫描期间稍等，不要反复回车。若窗口在后面，可从任务栏找到它。

### 6.2 认识选段窗口

- `Frame`：帧进度条，用鼠标拖动到不同画面。
- `Time`：当前画面在原视频中的秒数。
- `Frame 0/...`：当前帧序号，从0开始。
- `A: not set`：还没标记开始。
- `B: not set`：还没标记结束。

窗口里的英文是为了避免OpenCV窗口出现中文乱码。手册中的按键含义如下：

| 按键 | 作用 |
|---|---|
| 空格 | 播放或暂停 |
| `J` | 暂停并往前一帧 |
| `K` | 暂停并往后一帧 |
| `A` | 将当前帧记为开始位置 |
| `B` | 将当前帧记为结束位置 |
| `S` | 保存已标记范围并关闭窗口 |
| `Q` 或 `Esc` | 退出，不保存本次选择 |

操作前单击视频画面让窗口获得焦点，切到英文输入法，关闭Caps Lock。文中按键用大写字母标名称，实际直接按对应字母键，不按Shift。按键不要输入到PowerShell里。

### 6.3 先完整回放一次

1. 单击视频画面。
2. 按空格开始播放。
3. 看清哪个时间段是准备、正式动作、结束。
4. 再按空格暂停。
5. 初次操作建议先完整看一遍，不急着按A、B。

### 6.4 标记开始位置A

1. 暂停视频。
2. 拖动 `Frame` 滑条到动作开始之前。
3. 用 `J` 向前一帧或 `K` 向后一帧微调。
4. 保留短暂准备过程，不要选到动作已经进行一半的位置。
5. 按 `A`。
6. 检查窗口下方由 `A: not set` 变成具体秒数，例如 `A: 1.233s`。
7. 这个数字只是示例；你的时间以当前录像为准。

### 6.5 标记结束位置B

1. 拖动滑条到完整动作结束之后。
2. 使用 `J`、`K` 微调。
3. 保留动作完成后的真实尾段；要检查自动收尾时，不要把收手、双手出画的尾段裁掉。
4. 按 `B`。
5. 检查下方出现具体结束秒数，例如 `B: 5.600s`。
6. B必须大于A，且两者至少相隔0.5秒。0.5秒只是工具技术下限，不表示任意动作半秒就足够。

### 6.6 标错了怎么办

- A标错：拖到正确开始位置，再按一次 `A`，覆盖当前窗口内的开始标记。
- B标错：拖到正确结束位置，再按一次 `B`。
- 整体想取消：按 `Q`，不保存。
- 还没按S时，修改标记不会改变原视频。

### 6.7 保存范围

1. 核对A、B对应的是完整动作，而不是为了让结果好看随意删掉失败部分。
2. 按 `S`。
3. 窗口关闭后回到PowerShell。
4. 查看是否显示“已保存选段”、起止秒数和帧数。
5. 再运行下面命令查看记录：

```powershell
Get-Content -LiteralPath ".\data\mediapipe-demo\selections\need-01.json" -Encoding UTF8
```

重点看 `source`、`startSeconds`、`endSecondsInclusive`、`startFrame`、`endFrameInclusive`。

结束帧包含在选段内，所以帧数等于“结束帧序号－开始帧序号＋1”。范围记在JSON里，原MP4没有被裁剪或覆盖。

**JSON选段不会自动同步到网页训练卡。** 后文如要正式训练，需要在网页中录入同一原片的起止秒数。

### 6.8 已经知道秒数时的备用方式

一般优先用上面的可视化选段。如果你已经回看并明确要从第2.0秒选到第5.0秒，可以使用：

```powershell
& ".\.venv-sign\Scripts\python.exe" -B ".\scripts\mediapipe-demo.py" mark --video ".\data\mediapipe-demo\input\need-01.mp4" --start 2.0 --end 5.0 --selection ".\data\mediapipe-demo\selections\need-01-manual.json"
```

2.0和5.0是写法示例，必须换成你的真实时间。原片没有那么长时命令会报错。小数用英文句点，不用中文逗号。工具会选取范围内的实际视频帧，因此保存的秒数可能与输入数值有一帧内的差异。

## 7 输入命令提取MediaPipe骨架

### 7.1 确定这次使用哪个选段记录

本章继续使用可视化操作保存的 `need-01.json`。如果你使用了备用命令生成 `need-01-manual.json`，把下面 `--selection` 后面的文件名改为那个文件名。

### 7.2 执行提取

复制整行到PowerShell，按回车：

```powershell
& ".\.venv-sign\Scripts\python.exe" -B ".\scripts\mediapipe-demo.py" extract --selection ".\data\mediapipe-demo\selections\need-01.json" --out ".\data\mediapipe-demo\output\need-01-run01"
```

参数说明：

- `extract`：执行骨架及特征提取。
- `--selection`：读取第6章保存的原片路径和起止范围。
- `--out`：本次输出到哪里。工具会新建这个目录；目录已存在时拒绝覆盖。
- `run01`：第一次处理的输出编号。重新处理时换成 `run02`、`run03`，保留前次结果便于对照。

### 7.3 这时程序具体在做什么

1. 读取选段JSON。
2. 重新计算原视频哈希，确认视频自选段后没有被替换。
3. 打开原视频，按顺序解码。
4. 跳过开始位置之前的帧，处理选定范围内的帧。
5. 将画面缩放到长边最多640像素，控制演示处理量。
6. 调用项目现有的MediaPipe Hands和Pose跟踪图。
7. 获得每只检测到的手的21个点，以及身体姿态参照。
8. 复用项目 `observe_unified_bgr` 生成每帧178维特征。
9. 在画面上画手部点线和肩肘腕参照线。
10. 同时写入原片段、骨架片段、左右对照视频、关键点数据和特征数组。
11. 全部视频写完、关闭文件后，写出 `summary.json` 作为完成摘要。

提取使用已有MediaPipe模型进行推理；这条命令没有训练MediaPipe，也没有训练TCN。

### 7.4 观察终端进度

通常会出现类似下面的进度行：

```text
处理 1/121 帧 | 原片时间 1.200s
处理 30/121 帧 | 原片时间 2.167s
处理 60/121 帧 | 原片时间 3.167s
...
```

以上是格式示意，不是你的预定结果。真实总帧数和时间以本次输出为准。

程序处理期间不弹出实时骨架窗口。你先看终端进度，完成后再打开生成的视频。不要因为一时没弹视频就重复执行提取。

### 7.5 怎样判断完成

1. 终端出现“完成：……”和输出目录。
2. 终端出现特征形状和“检测到手的帧数”。
3. PowerShell重新出现 `PS E:\Desktop\项目>` 提示符。
4. 输出目录内有 `summary.json`，其中 `status` 是 `completed`。

若只有一部分AVI但没有完成摘要，可能是处理中断，不能将其当作完整成功结果。需要停止时可在PowerShell按 `Ctrl+C`；重试使用新输出目录。

## 8 找到输出文件并理解每个文件

用资源管理器打开：

```text
E:\Desktop\项目\data\mediapipe-demo\output\need-01-run01
```

也可在PowerShell列出文件：

```powershell
Get-ChildItem -LiteralPath ".\data\mediapipe-demo\output\need-01-run01"
```

| 文件名 | 内容 | 用途 |
|---|---|---|
| `selection.json` | 本次使用的选段记录副本 | 追溯原视频和起止范围 |
| `original.avi` | 所选片段的缩放画面，无骨架 | 观看动作本身；不是原MP4的字节副本 |
| `skeleton.avi` | 同一片段叠加手部和身体参照线 | 检查关键点跟踪 |
| `comparison.avi` | 左边原画面、右边骨架画面 | 同步并排演示，推荐优先使用 |
| `start.png` | 选段第一帧对照截图 | 讲解起点 |
| `middle.png` | 选段中间帧对照截图 | 讲解中间过程；不保证恰好是语义关键姿势 |
| `end.png` | 选段最后一帧对照截图 | 讲解结尾 |
| `features.npy` | N行、178列的数值数组 | 展示模型输入的数据形状 |
| `landmarks.json` | 逐帧原片时间、手部点、身体点和左右手标签 | 检查坐标及实际时间 |
| `summary.json` | 处理状态、帧数、哈希、版本、跟踪质量 | 核对是否完整处理 |

导出的AVI没有音频。原视频是可变帧率时，AVI采用原片标称帧率进行等间隔预览；分析用的实际逐帧时间保存在 `landmarks.json`。因此精确时间以JSON为准，不从AVI播放长度反推。

## 10 查看骨架数据怎样变成模型输入

### 10.1 读取处理摘要

重点字段：

| 字段 | 你该如何解释 |
|---|---|
| `status` | `completed`表示导出流程完成 |
| `featureShape` | 例如 `[121, 178]`，表示121帧，每帧178个特征值 |
| `handsDetectedFrames` | 至少检测到一只手的帧数，不是识别正确帧数 |
| `quality.passed` | 是否通过项目的基础跟踪质量条件，不代表手语语义正确 |
| `sourceTimeRange` | 选段在原视频中的起止时间 |
| `timestampFallbackUsed` | 是否在解码时间戳异常时按有效帧率回退计算 |
| `sourceSha256` | 原视频内容校验值，供核对来源 |

### 10.2 在终端打印特征数组大小


解释方法：

“这里每一行对应一个时间点，每一列对应一个特征。178不是178个骨骼点，而是手部、身体参照及相关状态经过统一处理后的特征数量。后面的TCN要看连续多行，学习动作如何随时间变化。”

缺失信息按项目协议和有效性标记处理，不靠人为补造完整手部轨迹。某些值为0不等于代码失败，需要结合有效性和质量字段理解。

## 13 常见问题与处理方法

### 13.1 PowerShell提示找不到命令或路径

1. 重新运行 `Set-Location -LiteralPath "E:\Desktop\项目"`。
2. 检查命令最前面的 `&` 是否保留。
3. 检查引号是英文双引号，不是中文弯引号。
4. 检查脚本文件名有连字符：`mediapipe-demo.py`。
5. 用 `Test-Path` 分别检查Python路径、脚本路径和视频路径。

### 13.2 出现缺少cv2或mediapipe

先看是不是用了系统 `python`。本手册指定 `.\.venv-sign\Scripts\python.exe`。当前电脑该环境已验证；若环境被删除或换机，需要按项目部署说明恢复，不在现场临时升级全部依赖。

### 13.3 视频打不开

1. 用Windows播放器确认原视频能完整播放。
2. 查看是否文件名重复了 `.mp4.mp4`。
3. 检查相机录制是否已正常停止并保存。
4. 不能通过重命名把MOV或其他编码变成MP4。
5. 原编码无法解码时，优先用Windows相机重新录制本次演示素材。

### 13.4 选段窗口没有响应字母键

1. 单击视频画面。
2. 切英文输入法，关闭Caps Lock。
3. 按字母键本身，不按Shift。
4. 不要在PowerShell文本区域输入A/B/S。
5. 如窗口藏在后面，从任务栏切回 `MediaPipe Demo - Select`。

### 13.5 按S没有保存

看A和B是否都已设置，B是否晚于A，范围是否至少0.5秒。窗口提示 `Set A before B` 时，重新标记。直接关闭窗口或按Q属于取消，不会保存。

### 13.6 提示选段文件或输出目录已存在

这是防止覆盖旧结果。重新选段时改用 `need-01-v2.json`；重新提取时改用 `need-01-run02`，并确保下一条命令引用的是新文件。不要为了重试先把所有旧资料删除。

### 13.7 提示原视频已经变化

视频选段记录绑定了内容哈希。原片被重新编码、剪辑或替换后，要重新运行select生成新记录，不能手工改哈希绕过核对。

### 13.8 视频有画面但没有骨架

1. 查看 `handsDetectedFrames` 是否为0。
2. 确认选段包含手，不是选中了开始前的空画面。
3. 检查双手是否太小、模糊、背光或互相遮挡。
4. 检查手是否完整入镜。
5. 调整拍摄后重录一条，以新文件名重新选段与提取。
6. 不画假骨架来补演示，也不把“文件生成了”讲成“检测准确”。

### 13.9 有手骨架但质量不通过

查看摘要中的 `handFrames`、`internalCoverage`、`bodyCoverage`。手部跟踪帧太少、动作中断跟踪、双肩参照不足都可能导致失败。质量检查不审定动作的专业语义；回看画面后决定补录内容。

### 13.10 AVI双击打不开

直接使用第9章的 `play` 命令，它通过已验证的OpenCV解码，不依赖系统默认播放器是否支持AVI。没有声音是导出设计，不是麦克风坏了。

### 13.11 提取中断或长时间没有完成

1. 看终端是否仍有进度或明确错误。
2. 需要停止时按Ctrl+C。
3. 已有部分输出保留，使用新run目录重试。
4. 原MP4不变；未产生 `summary.json` 的目录不作为完整结果展示。
5. 训练或别的重计算任务同时运行时，先合理安排任务，不承诺固定几秒完成。
