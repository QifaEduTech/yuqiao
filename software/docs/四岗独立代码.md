# 语桥四岗独立代码

更新：2026-11-23。四个模块已拆入项目现有层，各自独立运行，互不 import；不是把四个功能塞进现有 Web。
视觉岗使用项目的 MediaPipe Hands 和 Pose 跟踪图，先运行 check 核对环境，再对选定录像逐帧提取。

|---|---|---|---|---|
| 01 大模型工程师 | `server/llm/minicpm_camera.py` | 算法/模型层 | `python server/llm/minicpm_camera.py --demo` | `outputs/four-role/01_大模型工程师/observation.json` |
| 02 视觉工程师 | `scripts/mediapipe-demo.py` | 骨架与时序特征 | `.\.venv-sign\Scripts\python.exe -B scripts/mediapipe-demo.py check` | `comparison.avi`、`features.npy`、`summary.json` |

四个模块不导入 `server/app.mjs`、不读写 MySQL、不进入实时识别链路；它们是独立演示代码，运行结果不等于生产功能。

### 02 视觉工程师操作

在软件根目录运行表中的环境检查。按[详细操作手册](mediapipe-demo/MediaPipe视频选段与骨架提取详细操作手册.md)用 `select` 回放原录像，按 A、B 标记时间范围，按 S 保存。运行 `extract` 导出原片与骨架的同步对照视频和每帧 178 维特征，再用 `play` 播放。将每次结果放到 `data/mediapipe-demo/output/` 下独立的运行目录，项目驾驶舱会读取最近写入的 `summary.json`。统一手语分类模型在训练页训练。


### Windows 换机运行

- 项目经理模块只依赖 Python 标准库，**不需要 `.venv`**。Windows 双击 `Run-ProjectCockpit.cmd`，它会自动寻找本机的 `py -3` 或 `python`；也可以用 `py -3 scripts/project_cockpit.py`。
- 不要把其他电脑的 `.venv`、`.venv-sign`、`.venv-anny` 整个复制过来；这些目录里写死了原机器的 Python 绝对路径，换机后会报 `did not find executable ...`。新机按本文档重新建环境。
- 出现 `did not find executable at C:/Users/.../python.exe` 时，不是 `project_cockpit.py` 的问题，而是使用了旧的虚拟环境；改用 `Run-ProjectCockpit.cmd` 或系统 Python 即可。

## 需要敲的部分怎么标

- 01、03、04 的文件里有一段用 `# ===== 展示代码 START/END =====` 包住的代码。
- 行尾带 `# [敲]` 的行，是现场需要敲出的重点行；其余行是上下文，可不敲。
- [四岗代码摘录](四岗代码摘录.md) 把四段代码、文件地址、源文件行号、需要敲的行号集中列出。
- [four-role-code-excerpt.json](assets/four-role-code-excerpt.json) 是同一份标注的机器可读版，55 分钟稿的代码附录由它生成。
- 摘录不能单独运行；运行请使用完整文件。

## 四个模块怎么独立

```text
摄像头/图片
  ├─ 01 MiniCPM-V 视觉观察  →  outputs/four-role/01_大模型工程师/observation.json
  ├─ 02 录像选段 → MediaPipe手部/姿态关键点 → 骨架对照视频、178维特征和摘要
  └─ 03 FastAPI 工作流编排  →  outputs/four-role/03_AI应用工程师/workflow.json
04 项目驾驶舱 ← 读取项目计划 + 工作簿 + 01/02/03 的输出
```

- 01、02、03、04 之间没有 Python import。
- 03 只有在显式传入 `--vision-url` / `--llm-url` 时才走 HTTP；02 的视频提取使用 CLI，HTTP 适配器需要另加轻量包装；不传 URL 时使用 mock 适配器，仍能独立完成一次工作流。
- 04 的 `--live` 只是可选健康检查；不连也能读计划和输出文件出报告。

## 真实运行依赖

| 模块 | demo | 真实模式 |
|---|---|---|
| 01 | 标准库 | `opencv-python`；本地模型另需 `torch`、`transformers`、`Pillow` 和 MiniCPM-V 权重，或使用 `--endpoint` |
| 02 | 项目 .venv-sign 环境 | MediaPipe、OpenCV、NumPy |
| 03 | 标准库 | `fastapi`、`uvicorn`、`python-multipart` |
| 04 | 标准库 | 无额外依赖 |

建议分开建环境，不要把四个模块的依赖装进同一个环境：

```bash
python -m venv .venv-llm
python -m venv .venv-app
```

## 不能说的话

- MiniCPM-V 的输出现场叫“视觉观察/候选”，不能叫“手语翻译结果”。
- 02 的质量指标反映手部和身体跟踪情况。词语识别效果以统一模型的测试报告为准。
- FastAPI 不诊断、不决定挂号/检查/接诊。
- 项目经理只报计划和证据状态，不把“文件存在”写成“功能完成”。
- 所有候选都带 `human_review_required: true`，需要使用者或专业人员确认。
