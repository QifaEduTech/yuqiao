# 语桥四岗独立代码

更新：2026-11-11。四个模块已拆入项目现有层，各自独立运行，互不 import；不是把四个功能塞进现有 Web。
每个模块都有 `--demo`，不接摄像头、不装重型模型也能跑出自己的结果。

## 四个位置

| 模块 | 文件地址 | 所在层 | 独立运行 | 独立产出 |
|---|---|---|---|---|
| 01 大模型工程师 | `server/llm/minicpm_camera.py` | 算法/模型层 | `python server/llm/minicpm_camera.py --demo` | `outputs/four-role/01_大模型工程师/observation.json` |
| 02 视觉工程师 | `server/vision/yolo_segmentation.py` | 视觉/算法层 | `python server/vision/yolo_segmentation.py --demo` | `outputs/four-role/02_视觉工程师/segmentation.json` |
| 03 AI应用工程师 | `server/service/fastapi_workflow.py` | 服务/接口层 | `python server/service/fastapi_workflow.py --demo` | `outputs/four-role/03_AI应用工程师/workflow.json` |
| 04 项目经理 | `scripts/project_cockpit.py` | 项目管理/工具层 | `python scripts/project_cockpit.py` | `outputs/four-role/04_项目经理/standup.md` |

四个模块不导入 `server/app.mjs`、不读写 MySQL、不进入实时识别链路；它们是独立演示代码，运行结果不等于生产功能。

## 需要敲的部分怎么标

- 每个文件里有一段用 `# ===== 展示代码 START/END =====` 包住的代码。
- 行尾带 `# [敲]` 的行，是现场需要敲出的重点行；其余行是上下文，可不敲。
- [四岗代码摘录](四岗代码摘录.md) 把四段代码、文件地址、源文件行号、需要敲的行号集中列出。
- [four-role-code-excerpt.json](assets/four-role-code-excerpt.json) 是同一份标注的机器可读版，55 分钟稿的代码附录由它生成。
- 摘录不能单独运行；运行请使用完整文件。

## 四个模块怎么独立

```text
摄像头/图片
  ├─ 01 MiniCPM-V 视觉观察  →  outputs/four-role/01_大模型工程师/observation.json
  ├─ 02 YOLO 实例分割       →  outputs/four-role/02_视觉工程师/segmentation.json
  └─ 03 FastAPI 工作流编排  →  outputs/four-role/03_AI应用工程师/workflow.json
04 项目驾驶舱 ← 读取项目计划 + 工作簿 + 01/02/03 的输出
```

- 01、02、03、04 之间没有 Python import。
- 03 只有在显式传入 `--vision-url` / `--llm-url` 时才走 HTTP；01/02 当前是 CLI，HTTP 适配器需要另加轻量包装；不传 URL 时使用 mock 适配器，仍能独立完成一次工作流。
- 04 的 `--live` 只是可选健康检查；不连也能读计划和输出文件出报告。

## 真实运行依赖

| 模块 | demo | 真实模式 |
|---|---|---|
| 01 | 标准库 | `opencv-python`；本地模型另需 `torch`、`transformers`、`Pillow` 和 MiniCPM-V 权重，或使用 `--endpoint` |
| 02 | 标准库 | `ultralytics`、`opencv-python`、`numpy` |
| 03 | 标准库 | `fastapi`、`uvicorn`、`python-multipart` |
| 04 | 标准库 | 无额外依赖 |

建议分开建环境，不要把四个模块的依赖装进同一个环境：

```bash
python -m venv .venv-llm
python -m venv .venv-vision
python -m venv .venv-app
```

## 不能说的话

- MiniCPM-V 的输出现场叫“视觉观察/候选”，不能叫“手语翻译结果”。
- YOLO COCO 没有 `hand` 类别；人物/物体分割不能冒充手部实例分割。
- FastAPI 不诊断、不决定挂号/检查/接诊。
- 项目经理只报计划和证据状态，不把“文件存在”写成“功能完成”。
- 所有候选都带 `human_review_required: true`，需要使用者或专业人员确认。

## 运行结果

四个 `--demo` 已在本机实际运行通过：

- 01：输出 1 条有证据的“需要”候选，自动丢弃 1 条无证据的“帮助”候选。
- 02：输出 person/chair 两个演示实例，并生成演示图。
- 03：并行 mock 视觉与大模型，工作流完成并丢弃无证据候选。
- 04：读取医院互助工作簿，统计 30 个动作、4 个内置、26 个新增、11 个已有示范。

这些是接口与流程演示，不是识别准确率，也不是医院现场验收。
