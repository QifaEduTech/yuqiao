# 语桥四岗现场演示代码

前三岗用项目现有功能演示录像分区、骨架与识别、数字人回应。以下命令均从项目根目录执行。

| 岗位 | 实操入口 | 驾驶舱读取的结果 |
|---|---|---|
| 01 大模型工程师 | 训练页、`scripts/four-role-samples.mjs` | `outputs/four-role/01_大模型工程师/observation.json` |
| 02 视觉工程师 | `scripts/mediapipe-demo.py` 的选段、提取、对照与模型测试 | `data/mediapipe-demo/output/<本轮目录>/summary.json` |
| 03 AI应用工程师 | 语桥首页、`scripts/four-role-avatar.mjs` | `outputs/four-role/03_AI应用工程师/workflow.json` |
| 04 项目经理 | `Run-ProjectCockpit.cmd` 或 `py -3 scripts/project_cockpit.py` | `outputs/four-role/04_项目经理/standup.md`、`.html` 和 `.json` |

## 01 录入样本并检查分区

在训练页打开“需要”任务，回看已授权录像并核对标签和起止时间。用下节的 `mark` 将同一时间范围保存为选段 JSON，也可以用 `select` 逐帧标记。把原片和选段文件交给2号。

把下例保存为 `data/mediapipe-demo/selections/samples.json`，用实际存在的文件名替换示例。各行应当来自不同原片。只在有可靠记录时标记真实拍摄组。

```json
{
  "words": ["需要"],
  "samples": [
    {"selection": "background-01.json", "word": "背景", "split": "train"},
    {"selection": "background-02.json", "word": "背景", "split": "train"},
    {"selection": "need-01.json", "word": "需要", "split": "train", "group": "第一轮", "realGroupConfirmed": true},
    {"selection": "need-02.json", "word": "需要", "split": "train", "group": "第二轮", "realGroupConfirmed": true},
    {"selection": "need-test.json", "word": "需要", "split": "test"}
  ]
}
```

```powershell
node scripts/four-role-samples.mjs .\data\mediapipe-demo\selections\samples.json
```

命令重新计算原片的 SHA-256，并调用正式训练使用的分区函数。通过时输出拟合、内部检查和测试数量。准备一个单独的冲突清单，将一条选段同时填到两个分区，可以现场展示程序拦截的原因。清单只核对本批演示文件，正式登记和训练从训练页操作。读取驾驶舱时核对摘要时间。

## 02 骨架和指定模型测试

下面的秒数是示例，以1号交接的实际范围为准。选段按键和完整过程见[MediaPipe手册](mediapipe-demo/MediaPipe视频选段与骨架提取详细操作手册.md)。

```powershell
.\.venv-sign\Scripts\python.exe -B scripts/mediapipe-demo.py mark --video .\data\mediapipe-demo\input\need-01.mp4 --start 2.0 --end 5.0 --selection .\data\mediapipe-demo\selections\need-01.json
.\.venv-sign\Scripts\python.exe -B scripts/mediapipe-demo.py extract --selection .\data\mediapipe-demo\selections\need-01.json --out .\data\mediapipe-demo\output\need-01
.\.venv-sign\Scripts\python.exe -B scripts/mediapipe-demo.py play --video .\data\mediapipe-demo\output\need-01\comparison.avi
```

为另一条没参与训练和调参的录像单独生成 `need-test.json`，再用以下命令。模型目录需要包含 `model.json` 和 `weights.npz`，这里使用公开交付分支提供的六词权重。

```powershell
.\.venv-sign\Scripts\python.exe -B scripts/mediapipe-demo.py extract --selection .\data\mediapipe-demo\selections\need-test.json --out .\data\mediapipe-demo\output\need-test
.\.venv-sign\Scripts\python.exe -B scripts/mediapipe-demo.py test --run .\data\mediapipe-demo\output\need-test --model .\models\unified-sign\six-word-user-selection-v1 --expect 需要
```

`test.json` 分别记录权重哈希、整段分类、录像结束出词、自动收尾和与人工标签的对照。`--expect` 只用于核对结果。重新演示时使用新输出目录，已有报告会保留。整批训练和逐词指标在训练页查看。

## 03 文字匹配和数字人播放

启动语桥 Web 和后端。命令默认连接本机 `127.0.0.1:5174`，如启动器显示端口不同，使用 `--url` 指定语桥的实际本机地址。

```powershell
node scripts/four-role-avatar.mjs --text "我需要帮助"
node scripts/four-role-avatar.mjs --text "我想请医生帮忙"
```

脚本调用与首页相同的动作匹配接口，读取并汇报实际返回的动作顺序。回到首页提交相同文字，现场查看数字人是否按顺序播放，再修改或清空文字核对停止。摘要记录接口结果，播放器表现由现场观察。需要展示缺词时提前彩排，区分规则命中、动作缺口和本机语言服务不可用。
