# 公网部署

更新：2026-11-12。公网优先使用 **Cloudflare Tunnel**，不需要公网 IP、路由器端口映射
或本机 443 证书。当前已验证临时快速隧道；固定域名需要你提供 Cloudflare 账号、域名和
隧道令牌。

## 方案一：临时快速隧道（已验证，适合演示）

```text
Start-Public.cmd
```

脚本会：

1. 检查/安装 `cloudflared`（`tools/cloudflared`，不进 Git）。
2. 启动 `cloudflared tunnel --url http://127.0.0.1:8080`。
3. 从日志读取 `https://*.trycloudflare.com`。
4. 用该域名生成 Nginx 配置，设置 `APP_ORIGINS=https://该域名`、`COOKIE_SECURE=true`。
5. 启动 Node/Nginx，打印公网 URL 并打开浏览器。

特点：

- 公网 HTTPS 由 Cloudflare 边缘提供，本地不需要证书。
- URL 每次启动都会变化。
- URL 是公开的，任何人拿到都能打开登录页；**验证完请立即 `Stop-Yuqiao.cmd`**。
- 适合比赛演示、远程联调，不适合长期生产。

停止：

```text
Stop-Yuqiao.cmd
```

停止脚本会先停 `cloudflared`，再停 Nginx/Node。

## 方案二：Cloudflare 固定域名（推荐长期使用）

需要：

1. Cloudflare 账号和一个已接入 Cloudflare 的域名。
2. 在 Cloudflare Zero Trust → Networks → Tunnels 创建隧道，复制 Tunnel Token。
3. 在隧道 Public Hostname 里添加：
   - Hostname：`yuqiao.example.com`
   - Service：`http://127.0.0.1:8080`
4. 在本机设置令牌（不要写进仓库）：

```powershell
$env:CLOUDFLARE_TUNNEL_TOKEN='你的隧道令牌'
```

5. 启动：

```text
Start-Yuqiao.cmd -Public -PublicDomain yuqiao.example.com
```

脚本会启动本地 Nginx HTTP 8080 + Node，然后用命名隧道连到 Cloudflare。公网入口是
`https://yuqiao.example.com/`。`APP_ORIGINS` 会自动包含该域名，Cookie 为 Secure。

安全建议：

- 令牌只放环境变量或本机密码管理器；不要提交 `.env`、脚本或截图。
- Cloudflare 侧开启 WAF/速率限制；本机 Nginx 已对 `/api/auth/` 做 3r/s 限流。
- 不要在公开环境保留默认/弱密码账号；注册入口是开放的，演示后应停隧道。
- 不要把 MySQL 3306、Ollama 11434、Node 5174 加入隧道 Public Hostname。

## 方案三：路由器端口映射 + 本机证书

适用于有公网 IPv4、能管理路由器的环境；如果运营商是 CGNAT，则不可用。

1. 确认公网 IP 和 DDNS 域名。
2. 路由器把 80/443（或 8443）转发到本机；只转发需要的端口。
3. 域名证书放到：

```text
%LOCALAPPDATA%\Yuqiao\nginx-runtime\certs\
```

4. 生成公网配置（需要管理员权限监听 80/443）：

```powershell
node scripts/prepare-nginx.mjs --https --public --domain yuqiao.example.com ^
  --http-port 80 --https-port 443 ^
  --cert "%LOCALAPPDATA%\Yuqiao\nginx-runtime\certs\fullchain.pem" ^
  --key  "%LOCALAPPDATA%\Yuqiao\nginx-runtime\certs\privkey.pem"
```

5. 用同一证书配置启动 Node：

```powershell
$env:APP_ORIGINS='https://yuqiao.example.com'
$env:COOKIE_SECURE='true'
```

6. 管理员防火墙只放行 80/443 的入站；不要放行 3306/11434。

当前脚本没有自动申请 Let's Encrypt 证书，也没有改路由器；上述步骤需要你提供域名、
证书和公网入口。不要把“配置模板存在”说成“公网已上线”。

## 方案四：云服务器/VPS

如果要把服务长期放在云上，建议：

- Linux VPS + Nginx + Node + MySQL，或继续用 Windows 主机；
- 只暴露 Nginx 80/443；MySQL 只监听本机；
- 模型权重、Python 环境、Ollama 按 `docs/Windows-migration.md` 重建；
- 用 systemd/Windows 服务托管，不依赖登录会话；
- 备份 MySQL 和 `data/media`，密钥用目标机器的 DPAPI/密钥管理重新配置。

本项目当前验证的是 Windows 本机；VPS 迁移需要单独验收，不能直接沿用本机路径。

## 安全底线

公网部署前至少确认：

- [ ] 公网只暴露 Nginx 80/443 或 Cloudflare 隧道，不暴露 5174、3306、11434。
- [ ] `APP_ORIGINS` 只包含实际域名和本机入口，不使用通配符。
- [ ] `COOKIE_SECURE=true`，HTTPS 入口生效。
- [ ] 账号密码不是弱口令；演示账号与真实账号分开。
- [ ] 临时隧道用完即停；固定域名有访问日志和速率限制。
- [ ] 不把 `data/`、`.env`、数据库备份、逐字稿、私人录像放进公开目录。
- [ ] MySQL 定期备份；恢复流程在新机实际演练过。
- [ ] 公开页面不展示准确率、医疗结论或“已受理”等未经证实的承诺。
